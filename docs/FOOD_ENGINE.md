# FOOD_ENGINE

The food-composition & recipe-calculation engine. Source: `src/data/food/`, `src/utils/recipeNutrition.ts`, `src/utils/recipeCalc.ts`, `scripts/`. Design rationale + source licences: `docs/FOOD_DATA_ENGINE_AUDIT.md`, `docs/food-data-sources.md`.

## How foods are stored
Everything is a provider-independent **`CanonicalFood`** with **`CanonicalNutrition` per 100 g of edible portion**. Rules: every nutrient is **unit-suffixed** and **optional**; **missing = `undefined`, never 0**; each food carries `dataQuality` (completeness %, status, warnings) and `provenance` (dataset, version, retrievedAt, original units, transformations). Adapters map CoFID/FDC/OFF raw responses onto this model — the app never touches provider shapes.

## Food database
- **UK CoFID 2021** (primary): imported to `data/generated/cofid/` — **2,886 records** (`foods.json`, lazy-loaded; `index.json`; `meta.json`; validation report). OGL v3.0, Crown copyright, attributed in-app. Gitignored data artefact; regenerated by `import-cofid`.
- **Bundled subset** `recipeFoods.json`: only the CoFID records referenced by recipe ingredient links, shipped in the JS bundle for offline calc (`extract-recipe-foods`).
- **32 manual seed foods** (`seedFoods.ts`, `source: 'manual-reviewed'`, `status: 'estimated'`): unblock demo recipes before/around import; superseded by CoFID where a code exists.
- `foodStore.ts`: `ALL_LOCAL_FOODS = [...generatedCofid(bundled), ...SEED_FOODS]` (CoFID wins id collisions), `getLocalFood(id)` (sync, `BY_ID` map), `scoreFood(food, query)` 0–1.

## Nutrition lookups (search)
`providers/foodSearchService.ts` fan-out with transparent source labels, **never auto-selecting result #1**:
- **barcode** → Open Food Facts.
- **branded** → OFF only.
- **generic** → CoFID-local first; USDA FDC fallback only if fewer than 3 strong local hits (score ≥0.7) and FDC enabled; merged, local ahead at equal score.
Providers: `cofidLocal` (offline; lazy-imports the full 2,886-record set on first search, caches, unions with bundled subset), `openFoodFacts` (live, `world.openfoodfacts.org/api/v2`, 15-min cache, User-Agent, branded/barcode only, ODbL never merged into shipped data), `foodDataCentral` (proxy stub → `/api/fdc`; empty if no proxy). `getLocalFood`/`resolveFoodById` power offline recipe calc.

## Recipe generation
No procedural/AI generation. Recipes are curated (49) and authored via the dev tool (`#authoring`): search canonical foods, pick food + preparation state, enter quantity, review resolved grams, auto-calculate, review missing nutrients, save. Quality rules (realistic quantities, complete method, raw/cooked not mixed, accurate tags/allergens, calculated-not-invented nutrition, meaningfully distinct) are documented for future library expansion.

## Recipe nutrition calculation
`utils/recipeNutrition.ts` (`NUTRIENT_KEYS`, ~48 fields):
- `ingredientContribution(food, grams) = per100g × grams / 100`.
- `computeRecipeNutrition(recipe, links)`: sums contributions using each ingredient's **gram weight** (from `householdMeasures.resolveGrams` — direct g, ml×density, reviewed household record, or generic fallback; refuses naive 1 ml = 1 g and warns on assumed density). Skips `optional` ingredients; emits warnings for unresolved links, **raw/cooked basis mismatch**, and **partial nutrients** (present in some-but-not-all foods → lower-bound). **No mid-calc rounding.**
- `portionCanonical`/`scaleCanonical`/`divideCanonical`/`sumCanonical` for per-serving, portion and day maths. Missing values are never coerced to 0; sums add only present values.
- Bridge to legacy display: `canonicalToNutritionData` (5 core macros fall back to 0 for display; optional stay undefined) and `canonicalToMicronutrientData` (missing omitted; **vitamin E µg ÷1000 → mg**; per-field rounding).
- `utils/recipeCalc.ts`: `isRecipeLinked` (in `FULLY_LINKED_RECIPE_IDS` **and** every ingredient linked), `getCalculatedNutrition` (+ completeness = mean of contributing foods'), and **`effectiveNutrition`** — calculated when linked, else the stored hand-authored values. **Currently 1/49 recipes are fully linked** (`bf-protein-porridge`); the rest still display authored numbers.

## Micronutrient scoring
The 24-micronutrient dashboard (`MicroDashboard`) compares day totals against reference intakes in `data/microDefs.ts` (label, unit, RDA). Values come from `micronutrients` (authored) or the calculated bridge. `NutritionScore` composes a general balance score from macro/target alignment and micronutrient coverage (planning signal, not medical).

## Condition scoring
Separate from composition — see [CONDITION_EVIDENCE](CONDITION_EVIDENCE.md). `scoring.ts` reads recipe nutrition + structured ingredient categories + evidence links to produce **categorical** relevance and dashboard metrics. Composition data alone never yields a condition claim (a magnesium-rich food is not "good for endometriosis").

## Food ranking
`utils/filters.ts` ranks recipes for a slot by ingredient/tag/prep/calorie/protein match. Food-search ranking uses `scoreFood` (exact 1.0 → alias 0.95 → prefix 0.9 → includes 0.8 → token-overlap `0.3 + 0.45×matched/qTokens`). Rankings are transparent and never auto-commit a match.

## Evidence weighting
Recipe-level evidence weighting is intentionally **not** a numeric multiplier into nutrition. Evidence influences the *condition relevance* factor `evidence-linked` (tiered by count) and the evidence panels — kept categorical and separate from composition, with whole-food vs supplement exposure distinguished (supplement-capsule evidence never transferred to a culinary quantity).

## Supplement integration
Supplements are evidence-library entries (`isSupplement`), never recommended as doses. They appear in the Supplement Evidence Centre; they do not affect nutrition calculation or recipes.

## Meal planning logic
Selections → `effectiveNutrition` × servings → `sumNutrition`/`sumMicros` day totals → dashboards, score, recommendations, shopping list. `utils/optimise.ts` proposes portion/recipe swaps toward targets. All offline.

## Shopping list generation
`utils/shopping.ts` aggregates selected recipes' ingredients, merges duplicates by name/unit, groups by `ShoppingCategory`, supports "owned" ticks. Derived at render; not persisted.
